# data/kb/ 형식

이 디렉터리는 아직 비어 있습니다 (Phase 2 STEP 4 결정: "구조만 먼저, 데이터는
비워둔다" — 실제 공식 자료 조사는 별도 트랙).

문서 하나 = 하위 디렉터리 하나.

```
data/kb/
└── <slug>/              예: fss-voice-phishing-report/
    ├── meta.json
    └── content.md
```

## meta.json

```jsonc
{
  "source_org": "금융감독원",
  "source_url": "https://...",   // kb_documents.source_url — 고유해야 함(재실행 시 upsert 기준)
  "tier": "T1",                   // T1 | T2 | T3 (§5-1)
  "title": "...",
  "collected_at": "2026-08-14",   // 이 문서를 수집한 날짜
  "verified_at": "2026-08-14",    // 선택: 사람이 최신성을 확인한 날짜
  "effective_from": "2026-02-01", // 선택: 이 절차/정보가 적용되기 시작한 날짜
  "category": "MONEY_SENT",       // 선택: 자유 텍스트. 아직 enum으로 고정하지 않음(보고 대기)
  "authority": "금융감독원"        // 선택: 이 절차에 대한 법적/행정적 관할기관
}
```

## content.md

절차를 **단계 단위**로 자른다(문단 무시, §5-2). 각 청크를 빈 줄 하나를 사이에 두고
`---`만 있는 줄로 구분한다. 청크 하나는 **최대 800자**.

```markdown
1단계 안내 원문...

---

2단계 안내 원문...
```

## 주의

T3(재단·협회 안내 페이지 등)는 **단독 근거로 쓸 수 없다** — §5-1 참고
(2026-02-01 신고번호 개편 때 한 T3 페이지가 구 번호를 그대로 보여준 사례 때문).
언론·블로그는 애초에 KB에 넣지 않는다.
